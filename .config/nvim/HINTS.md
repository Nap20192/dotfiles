## Философия

Конфиг построен на принципах:

- **Встроенные возможности Neovim** — автодополнение и сниппеты через `vim.lsp.completion`, не через nvim-cmp.
- **Минимум абстракций** — плагины только там, где без них не обойтись.
- **Единый стиль клавиш** — `<leader>f*` поиск, `<leader>g*` git, `<localleader>t*` тесты, `<localleader>b*` бенчмарки/сборка.
- **Dispatch для запуска** — тесты, линтеры и сборка уходят в фоновый job, результат попадает в quickfix.

## Навигация и файлы

### Oil — файловый менеджер

Oil позволяет редактировать файловую систему как буфер: переименовывать, удалять, перемещать файлы обычными vim-командами.

| Клавиша | Действие |
|---|---|
| `-` или `<leader>e` | Открыть oil в текущей директории |
| `<leader>E` | Открыть oil в плавающем окне |

**Внутри oil:**

| Клавиша | Действие |
|---|---|
| `<CR>` | Открыть файл/директорию |
| `l` | Перейти в директорию под курсором |
| `-` | Подняться на уровень выше |
| `_` | Открыть cwd |
| `<C-v>` | Открыть в вертикальном split |
| `<C-s>` | Открыть в горизонтальном split |
| `<C-t>` | Открыть в новой вкладке |
| `<C-p>` | Превью |
| `<C-r>` | Обновить |
| `g.` | Показать/скрыть скрытые файлы |
| `g?` | Помощь |

> Файлы из `.gitignore` скрыты автоматически. Файлы с `.` в начале тоже скрыты, но `g.` переключает их видимость.

## Treesitter

### Text objects

Работают в operator-pending (`d`, `c`, `y` и т.д.) и visual-режиме.

| Объект | Что выбирает |
|---|---|
| `af` / `if` | Функция целиком / только тело |
| `at` / `it` | Класс/тип целиком / тело |
| `aa` / `ia` | Параметр с запятой / без |
| `ai` / `ii` | if-блок целиком / только условие |
| `=r` | Правая часть присваивания |

**Примеры:**
- `daf` — удалить функцию целиком
- `cif` — заменить тело функции
- `yaf` — скопировать функцию
- `vaa` — выделить параметр для замены
- `d=r` — удалить правую часть присваивания

### Движение по функциям

| Клавиша | Действие |
|---|---|
| `]f` | К началу следующей функции |
| `]F` | К концу следующей функции |
| `[f` | К началу предыдущей функции |
| `[F` | К концу предыдущей функции |

### Swap параметров

| Клавиша | Действие |
|---|---|
| `<leader>man` | Переместить параметр вправо |
| `<leader>map` | Переместить параметр влево |
| `<leader>mfn` | Переместить функцию вниз |
| `<leader>mfp` | Переместить функцию вверх |

### Контекст

Строка в самом верху окна показывает, в какой функции/классе ты находишься.

| Клавиша | Действие |

| `[c` | Прыгнуть к строке контекста |

## Go

### Тесты (`<localleader>t*`)

| Клавиша | Команда | Описание |
|---|---|---|
| `,ta` | `GoTestAll` | Все тесты `./...` |
| `,tA` | `GoTestAll!` | Все тесты с `-short` |
| `,tp` | `GoTestPackage` | Тесты текущего пакета |
| `,tP` | `GoTestPackage!` | С `-short` |
| `,tf` | `GoTestFile` | Тесты файла |
| `,tF` | `GoTestFile!` | С `-short` |
| `,tt` | `GoTestFunction` | Тест под курсором (Treesitter) |
| `,tT` | `GoTestFunction!` | С `-short` |
| `,tl` | `GoTestLast` | Повторить последний тест |

> `!` добавляет `-short`. Count перед командой добавляет `-count=N -shuffle=on`, например `:3GoTestFile`.
> Build tags из `//go:build` добавляются автоматически.

### Бенчмарки (`<localleader>b*`)

| Клавиша | Описание |
|---|---|
| `,ba` / `,bA` | Все бенчмарки (с `-run=^$`) |
| `,bp` / `,bP` | Бенчмарки пакета |
| `,bf` / `,bF` | Бенчмарки файла |
| `,bb` / `,bB` | Бенчмарк под курсором |
| `,bl` | Повторить последний бенчмарк |

> `!` — только бенчмарки, без тестов (`-run=^$`). Count — `-count=N`.

### Сборка (`<localleader>b*`)

> Бенчмарки и сборка используют одни клавиши — в зависимости от контекста (в test-файлах — бенчмарки, иначе — сборка). Используй команды напрямую при конфликте.

| Команда | Описание |
|---|---|
| `:GoBuildAll` | `go build ./...` |
| `:GoBuildPackage` | `go build .` |
| `:GoBuildFile` | `go build <текущий файл>` |

## База данных (dadbod)

`:DBUI` — открыть интерфейс.

Сохранённые запросы лежат в `./sql/` относительно cwd.

| Клавиша | Действие |
|---|---|
| `<leader>ut` | Открыть/закрыть дерево истории изменений |

## Рабочий процесс

### Типичный сеанс кодинга на Go

```
1. Открыть проект: nvim .
2. <leader>ff     — найти нужный файл
3. <leader>fg     — найти где используется функция
4. grd            — перейти к определению
5. <C-o>          — вернуться назад
6. gra            — code action (fill struct, extract var и т.д.)
7. ,oc            — форматировать
8. ,tt            — запустить тест под курсором
9. <F5>           — если тест упал — отладить
```

### Рефакторинг функции

```
1. vaf            — выделить функцию целиком (treesitter)
2. <localleader>ef — extract function (gopls)
   — или —
3. v<выделить>    — выделить выражение
4. ,ev            — extract variable
```

### Работа с тестами

```
1. ,ot            — переключиться на _test.go
2. ,tt            — запустить тест под курсором
3. ,tl            — повторить (если чинишь итеративно)
4. ,ta            — прогнать всё перед коммитом
```

### Git workflow

```
1. <leader>gg     — открыть fugitive status
2. s              — stage нужные файлы/hunks
3. cc             — написать коммит
4. <leader>gps    — push
```

### Поиск по незнакомому коду

```
1. <leader>fs     — символы в файле (структуры, функции)
2. <leader>fS     — символы во всём workspace
3. grr            — найти все места где используется символ
4. <leader>fD     — посмотреть все диагностики workspace
```

### Быстрая навигация внутри файла

```
]f / [f           — прыгать между функциями
[c                — прыгнуть к контексту (в какой функции/классе ты)
za                — открыть/закрыть fold
zM / zR           — закрыть / открыть все fold
```
